# Cloud accounts in Orbit

Checked against official documentation on September 29, 2026.

1. **ChatGPT: install the official Codex CLI, then connect in Orbit.** Codex handles its own sign-in and token storage. Orbit starts that installation's App Server and accepts a ChatGPT-authenticated account for this connector. Inherited OpenAI API keys are removed from the child process environment, and an API-key account cannot silently become a subscription task. A plan's model access and usage limits still apply. [Codex authentication](https://learn.chatgpt.com/docs/auth)

2. **Enable the Orbit tools you want the task to use.** Orbit registers those tools in an `orbit` namespace with Codex's experimental dynamic-tool protocol. Tool requests return through Orbit's normal execution and approval checks. Actual text and approved screenshots are returned to the cloud model, so consider what is visible before approving a screenshot. Use a recent official Codex CLI supporting `dynamicTools` and `item/tool/call`; the protocol can change. [App Server documentation](https://learn.chatgpt.com/docs/app-server#dynamic-tool-calls-experimental)

3. **Review each requested action.** Orbit checks the tool name, active conversation, active turn and arguments before invoking a registered host tool. Host calls run one at a time. A declined or failed action returns `success: false`; stopping a task cancels waiting host calls and discards late results. Actions already completed cannot be undone by Stop. The host executor must check the supplied cancellation signal after approval and before execution.

4. **Understand the Codex permission boundary.** Orbit starts native Codex tools with a read-only sandbox, restricted network access and the `untrusted` approval policy. For sessions with Orbit tools, it also disables Codex's documented shell, subagent, app-connector and web-search features through temporary thread settings. These settings leave your normal Codex CLI configuration unchanged. They are not a disable-all-tools switch: remaining native reads or separately configured MCP integrations can still exist. Orbit bot tool selections constrain Orbit's registered tools, not every native capability. Additional native permission requests are reviewed separately. Do not treat a bot's tool list as an operating-system isolation guarantee. [Codex permissions](https://learn.chatgpt.com/docs/agent-approvals-security), [documented feature settings](https://learn.chatgpt.com/docs/config-file/config-reference)

5. **Claude: use an API key for Orbit's integrated agent.** Anthropic prohibits third-party apps from offering their own Claude.ai login or routing consumer subscription tokens. Anthropic separately permits users to sign in to an unmodified Claude Code binary under its stated hosting conditions. Orbit's external Claude links do not connect a Claude subscription to Orbit's tools. [Anthropic's authentication and credential rules](https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use)

6. **Gemini: use a Gemini API key for Orbit's integrated agent.** Google ended consumer Google sign-in for Gemini CLI on June 18, 2026, directing those users to Antigravity; Standard and Enterprise Code Assist are distinct. Antigravity's consumer terms prohibit third-party access through its OAuth. Opening an official Google product does not connect that product's subscription to Orbit. [Google's deprecation notice](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals), [Antigravity terms](https://antigravity.google/terms)

7. **Treat the bridge as a tested protocol integration, with live account testing still required.** Automated tests simulate the official JSON-RPC messages, scoped tool registration, actual tool results, screenshots, approval denials, serialization and cancellation. They do not log in to a real ChatGPT account or prove every released Codex CLI version is compatible. No Claude or Google account tokens are collected or reused by this bridge.

For maintainers: the current official wire types are [DynamicToolSpec](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/DynamicToolSpec.ts), [DynamicToolCallParams](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/DynamicToolCallParams.ts) and [DynamicToolCallResponse](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/DynamicToolCallResponse.ts). Orbit enables `initialize.params.capabilities.experimentalApi` and does not use the internal `chatgptAuthTokens` authentication mode.
