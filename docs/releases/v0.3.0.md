# Orbit 0.3.0 beta

Orbit now has a visible Chrome/Edge browser agent, reusable skills, bot profiles and installable instruction plugins. Cloud providers can operate Orbit tools without a local model.

## 1. Download and install

1. Choose the **AppImage** for Linux x64, **Setup EXE** for Windows x64, or the **Mac ZIP** matching Intel or Apple Silicon. These are unsigned beta builds; macOS packages are not notarized.
2. Follow **INSTALL.md** in Assets or [the installation guide](https://github.com/aaka3h/orbit-desktop/blob/v0.3.0/INSTALL.md).
3. Source ZIP files are for developers. **SHA256SUMS.txt** verifies the downloads.

## 2. Try the new agent features

1. Connect a cloud API, ChatGPT through the official Codex CLI, or a local model.
2. Open **Agents & skills → Browser**, enable Chrome or Edge, save and open the separate Orbit browser. Sign into websites manually.
3. Choose **Shopping assistant** or **Researcher**. Provide your budget, country and priorities, then review its requested actions. Detected checkout and purchase actions need explicit purchase confirmation. Passwords, verification codes and payment entry remain manual.
4. Create a skill or bot, or import the included example JSON plugin. Version 0.3 plugins contain instructions and bot profiles, not executable extensions or messaging integrations.
5. Read [the complete agent guide](https://github.com/aaka3h/orbit-desktop/blob/v0.3.0/docs/AGENTS-AND-SKILLS.md) and [account compatibility](https://github.com/aaka3h/orbit-desktop/blob/v0.3.0/docs/cloud-accounts.md).

## 3. Validation and limits

This release workflow requires automated tests and native package builds on Linux, Windows and macOS before publication, including a real Chromium fixture test. Linux Electron checks cover the actual desktop bridge, library UI, approvals, history and packaging. Fixtures use a fake shop; no real purchases or account credentials are used.

ChatGPT dynamic-tool support is experimental and protocol-tested; a live signed-in task is still unverified. Claude and Gemini integrations use API keys, not imported consumer subscription tokens. Interactive Windows/macOS installation, website compatibility and real account workflows need further testing. Purchase classification cannot understand every website's hidden behavior; inspect every action before approving. Browser network checks are not an OS sandbox.

The existing Hugging Face Hub, hardware estimates, theme settings and optional desktop controls remain available.
